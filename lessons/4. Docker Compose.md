## Why Docker Compose?

In modern engineering teams:

- applications rarely run as a single process
- systems are composed of multiple services

Examples:

- web app
- database
- Redis
- queue workers
- monitoring agents

Docker Compose allows developers to orchestrate these services locally.

## Create a Dockerfile

Create:

```text
Dockerfile
```

Add:

```dockerfile linenums="1"
FROM python:3.14-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["python", "run.py"]
```

## Understanding the Dockerfile

### `FROM`

```Dockerfile
FROM python:3.14-slim
```

Defines the base runtime image.

### `WORKDIR`

```Dockerfile
WORKDIR /app
```

Creates the application working directory inside the container.

### `COPY requirements.txt`

```Dockerfile
COPY requirements.txt .
```

Copies dependency definitions first.

This improves Docker layer caching performance.

### `RUN pip install`

```Dockerfile
RUN pip install --no-cache-dir -r requirements.txt
```

Installs Python dependencies inside the image.

### `COPY . .`

```Dockerfile
COPY . .
```

Copies the application source code.

### `EXPOSE`

```Dockerfile
EXPOSE 8000
```

Documents the application port.

### `CMD`

```Dockerfile
CMD ["python", "run.py"]
```

Defines the container startup command.

### Why .dockerignore Matters

This prevents:

- secrets
- virtual environments
- Git history
- SQLite databases

from being copied into Docker images.

This improves:

- security
- image size
- build speed

## Create `docker-compose.yml`

Create:

```text
docker-compose.yml
```

Add:

```yaml linenums="1"
services:
  db:
    image: postgres:18
    container_name: ads-postgres
    restart: always

    environment:
      POSTGRES_DB: ads_platform
      POSTGRES_USER: ads_user
      POSTGRES_PASSWORD: ads_password

    ports:
      - '5432:5432'

    volumes:
      - postgres_data:/var/lib/postgresql

    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}']
      interval: 5s
      timeout: 5s
      retries: 10

  web:
    build: .
    container_name: ads-platform

    depends_on:
      db:
        condition: service_healthy

    env_file:
      - .env

    ports:
      - '8000:8000'

volumes:
  postgres_data:
```

## Understanding `docker-compose.yml`

### `db` Service

```yaml
db:
```

Creates the PostgreSQL container.

This replaces:

- localhost
- hardcoded IPs
- machine-specific configuration

### `postgres:18`

```yaml
image: postgres:18
```

Uses the official PostgreSQL image.

### `volumes`

```yaml
volumes:
  - postgres_data:/var/lib/postgresql
```

Persists database data outside the container.

This is critical.

Containers are ephemeral:

- data must survive container restarts.

### `web` Service

```yaml
web:
```

Creates the FastAPI container.

### `depends_on`

```yaml
depends_on:
  db:
    condition: service_healthy
```

Ensures PostgreSQL starts first and is ready.

### `env_file`

```yaml
env_file:
  - .env
```

Injects environment variables into the container.

## Build and Start All Services

Run:

```bash
docker compose up --build
```

### What This Does

Docker Compose now:

- builds the FastAPI image
- starts PostgreSQL
- creates networking
- injects environment variables
- orchestrates both services together

This is now a multi-service platform.

## Test Persistence

Create some classified ads.

Press <kbd>CTRL</kbd><kbd>C</kbd> to stop the containers, or run:

```bash
docker compose down
```

```bash
docker compose up
```

```bash
docker compose up -d
```

Your ads should still exist.


- Compose creates an internal network

- ECS service discovery
