After completing this lesson, we will understand:

- why environment configuration matters

- hardcodes SQLite configuration

- mixes configuration directly into source code

But production systems need:

- portability
- security
- environment-specific configuration
- deployment flexibility

We now begin evolving the application into a production-ready service.

## Add Environment Variables

Open `.env` and add:

```env
APP_ENV=development
APP_HOST=0.0.0.0
APP_PORT=8000

DEBUG=APP_ENV=="development"

DATABASE_URL="sqlite:///./ads.db"
```

### Why This Matters

This is the beginning of separating:

- code
- configuration
- secrets

This is one of the most important principles in platform engineering.

The application source code should remain identical across:

- local development
- staging
- production

Only configuration changes.

## Create a Central Configuration File

Inside the project, create:

```text
app/config.py
```

Add:

```python
import os
from dotenv import load_dotenv

load_dotenv()

APP_ENV = os.getenv("APP_ENV", "development")

APP_HOST = os.getenv("APP_HOST", "0.0.0.0")
APP_PORT = int(os.getenv("APP_PORT", 8000))

DEBUG = APP_ENV == "development"

DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./ads.db")
```

### What This File Does

This creates a single source of truth for application configuration.

Instead of hardcoded values scattered everywhere, the application now loads configuration centrally.

This pattern is used in:

- FastAPI
- Flask
- Django
- Node.js
- Go services
- Kubernetes workloads
- ECS containers

## Update the SQLite Configuration

Update:

```text
app/database.py
```

Add and delete these highlighted lines.

```diff
from sqlalchemy import create_engine
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import sessionmaker

- DATABASE_URL = "sqlite:///./ads.db"
+ from app.config import DATABASE_URL

engine = create_engine(
    DATABASE_URL,
    connect_args={"check_same_thread": False}
)

SessionLocal = sessionmaker(
    autocommit=False,
    autoflush=False,
    bind=engine
)

Base = declarative_base()
```

### Why This Matters

The application no longer assumes:

- SQLite
- local storage
- one fixed path

This prepares us for the next lessons:

- PostgreSQL
- RDS
- cloud deployment

without rewriting the application.

## Update the Application Startup Command

Instead of hardcoding ports inside the app startup command, use environment variables.

Create:

```python
run.py
```

Add:

```python
import uvicorn

from app.config import APP_HOST, APP_PORT, DEBUG

if __name__ == "__main__":
    uvicorn.run(
        "app.main:app",
        host=APP_HOST,
        port=APP_PORT,
        reload=DEBUG
    )
```

## Introduce Development vs Production Concepts

We should now understand:

| Environment | Purpose                    |
| ----------- | -------------------------- |
| Development | Local coding and debugging |
| Staging     | Pre-production testing     |
| Production  | Live customer traffic      |

Different environments use:

- different databases
- different secrets
- different domains
- different logging levels
- different infrastructure

But ideally:

- the same application code
